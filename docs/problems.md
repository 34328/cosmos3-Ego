# AR 联合模型共用问题清单

更新：2026-10-03。适用于 AR V0.1 / V0.2 / V0.3 / V0.3.1 / V0.4；后续版本继续维护本文件。原 [V0.2 问题清单](ar_v0.2/archive/problems_2026-10-01.md) 作为历史判断保留，最新状态以本页和各版本实验记录为准。

## 当前范围

当前优先解决**视频生成质量**：先让真实条件下的短段画面与手物运动可靠，再处理长序列的历史误差累积。

action 策略、57D/PCA15 表示、坐标系及模型架构暂时固定；C4/K8/H15 和联合生成方式沿用现有方案。这里的“固定”是保持方案，不是新增 action 参数冻结。已有 V0.3.1 对照按其获批配方解释，不能借排查视频再叠加 action 改动。

action 的腕误差、手形与视频中的手是否一致仍作为联合生成的观察项；优先级调整不等于已经证明 action 没有独立问题。原清单中的相机投影、积分漂移等保留为后续问题，暂不单独展开。

一次只推进一个问题：先复用存档和既有评测，只有证据缺口明确时才补最小验证；需要正式训练时另行确定单因素方案。

## 当前修正：AR 块边界与 VAE 时间上下文（2026-10-03）

用户观察到纯视频 AR IT2V **V0.1 step2000** 仍有内容生成质量问题，但没有旧联合版本明显的画面跳变。这不是正在训练的完整 segment V0.2 的质量结论；两者样本、时域和配方也不同，不能当作单因素对照。

已由代码确认旧联合 V0.3/V0.3.1 继承的三处行为：

1. `cosmos3_joint_video_hand_pose/src/ar_v02_model.py::_encode_vision_x0_tokens` 每块独立编码 `[U,V]`，明确重置 causal VAE 时间上下文，然后拼接 latent。
2. `src/ar_v02_inference.py::JointARSampler._next_condition_video` 将上一块解码后的末 RGB 帧再次单帧编码，作为下一块 U；generated history 反复执行 decode→encode。
3. `src/ar_v02_overlay.py::decode_video_chunks` 每块独立解码 `[U,V]` 后由展示路径拼接 RGB。相较之下，纯视频 V0.1 连续编码视频、按 latent 分块，生成后整条 latent 一次解码。

**结论：旧联合设计把 AR 分块与 VAE 时间上下文重置绑定，是画面跳变的重要嫌疑，尚未证明是唯一原因。** 不能据此宣称前缀 loss、action 或整个 DF 范式必然错误。gt-history 每块重新提供 GT 条件会引入预测回跳；renderer 并没有在块边界硬插下一块 GT U。旧 RGB stride2 的实时回放为 15 个不同 RGB 帧/秒、30fps 容器，会增加卡顿，与跨块跳变需分开判断。

用户已授权在**新联合 V0.4 文件和配置**中修正：连续视频编码后切 latent 块，生成延续同一 latent 序列，解码保留连续时间上下文；action 策略沿用最近 V0.3.1，核对原始时间对齐、条件索引、历史 KV 与边界连续性。不改变正在运行的纯视频预训练，不自动启动新的联合正式训练。此项结构修正优先于原表中 V4 的排队顺序；短段内容质量仍是独立问题。

旧 checkpoint/NPZ 的 `joint_chunk_cond_v1` 分块 latent 语义不能直接改用连续解码来冒充修复；新版本需明确格式标记并拒绝旧格式。用户另已授权删除旧联合 V0.3* 的 checkpoint、视频、NPZ 和缓存等产物，清理前排除活跃任务引用，保留代码与小型实验结论；相关历史路径应理解为曾经的来源，不保证清理后仍可读取。

V0.3.0 已完成3000步；按用户决定，step3000仅做视频展示，未做完整三档定量评测。最新完整定量结论来自2000步，不能写成3000步指标。V0.3.1 已补step1500固定六窗临时检查，尚不是正式heldout8/train16对照；不能用启动loss代替质量。

这些是质量现象，不是单因素因果结论。V0.2 与 V0.3 的训练步数、调度、监督和历史噪声不同；尚不能把差异全部归到 DF。V0.3 已采用单遍 DF，旧清单“DF尚未开启”已过时。

## 视频问题与处理顺序

| 顺序 | 要回答的问题 | 优先复用的证据 / 最小下一步 | 判定与后续 |
| --- | --- | --- | --- |
| **V1 · 当前** | **给定真实条件时，短段视频能否生成好？** 手、物体和背景从何时开始失真，运动是否从第一块就偏了？ | 使用既有 gt / generated 存档与统一网页：先看无跨块历史的第一块，再看每块真实条件重置后的短段。区分纹理破碎、手物形变与运动轨迹错误；展示固定的 train / heldout pick-and-place 窗口，不另挑好样本。 | 第一块或 gt 模式已经差，先处理短段生成；短段可靠而 generated 中后段变差，再进入 V3。gt 的后续块仍含历史，只能辅助定位，不能当成完全独立单块实验。 |
| **V2 · 排队** | **为什么运动没有学好？** 监督分配、训练覆盖或条件利用是否限制了目标块学习？ | 先消化已有 V0.3.1 同步数、同窗口、同σ对照：它仅去除前缀视频/action loss分子，保留原分母与历史梯度。结合 train16 和 heldout 结果区分训练分布拟合与泛化现象。 | 用画面、方向余弦、幅值比和PSNR判断；不以总loss回到0.13验收。只有结果指向某个因素时，再定下一项视频侧对照，不同时改采样、数据和优化。 |
| **V3 · 排队** | **为什么连续生成逐渐漂移？** | 在同checkpoint、同窗口和同σ下对照 gt / generated 的既有逐块曲线及长视频，找偏差开始扩大的位置；复用已有三档σ结果。 | 观察从早期到第17块的增量退化，避免把首块已有误差都算成历史累积。涉及缓存噪声等设置时一次只动一项。 |
| **V4 · 排队** | **块边界跳变来自预测重置，还是解码/时间对齐？** | 从已有视频检查边界前后。gt 重置造成的跳变与 generated 自身不连续分开记录；确认原始时间轴、逐块解码及条件帧的展示口径。 | 只有边界问题在短段质量改善后仍独立存在，才单独处理。不用插帧、平滑掩盖生成问题。 |

V1 首轮只形成一页简短结论：固定窗口中“哪一类错误、最早何时出现、gt与generated是否同样出现”。已有官方整段 image2video 结果可作视觉参考，但生成时域、解码方式和条件不同，不能据此判定“训练损伤了Nano”。官方双向起点的零样本AR也不是经过AR训练的上限。

## V1 研究更新：因果视频能力与联合适配（2026-10-02）

本轮仅阅读代码、现有实验及一手论文/仓库，没有启动新训练或评测。以下是下一轮方案依据，不是已批准的训练配方。

- **当前优先假设**：可靠的短段因果视频能力尚未建立，因果转换、手部数据域适配及新联合接口被放进同一轮训练。官方 Nano 已有视频和机器人 action 预训练，但仓内原配置为 `causal_training_strategy=none`、`video_temporal_causal=False`；“有官方 AR 推理接口”不等于该起点已训练当前块因果分布。V0.2/V0.3 已经在做 AR 微调，不能称为完全没有 AR 训练。
- **反证与规模**：V0.2 固定16窗300步已达到26.40dB（实验10.4），说明有限集合可以拟合，不能宣称整个链路完全失效。完整训练数据为744 episodes / 17.34小时；V0.3.0的3000条正式monitor记录累计121,356次clip采样，平均global batch40.452。trace覆盖全部4409个train segment，各26–29次，但每次重新随机选窗口，不能说某个精确展示窗已重复优化这么多次。重复与重叠片段不等于独立新数据。首块及gt-history差，使历史噪声和长rollout失配不足以单独解释问题。
- **任务条件**：实际使用segment的`text_normalized`，并非没有动作文本；但随机窗口复用整段caption。例如“load glass cups into dishwasher”覆盖约49秒，不能唯一确定当前一秒的动作相位。同块未来action也是待生成量，gt-history不等于把未来真实action作为视频控制输入。唯一GT的PSNR/方向余弦与合理动作生成需分别解释。
- **额外设计偏移**：当前逐块独立VAE编码并重复引入U/S边界；`speed_factor=.5`使模型内部RGB/action时间标度为7.5/15fps，原始数据为30Hz、RGB stride2。训练和推理使用相同配置，不能称为已证实的时间错配；这些改变增加适配负担，但尚未证明是主因。视频/action loss系数均1，也不能仅用loss标量大小推断梯度竞争。

建议顺序：复用原生Nano既有结果，并以固定动作短片检查一个成熟AR baseline；再决定是否开展保持现有结构的video-only因果适配，将短段视频能力独立验收后接回action联合训练。video-only不能仅把action loss置零而仍让随机未来action干扰视频。对照必须对齐可用首帧/历史和文本信息，保留各baseline原生采样与时域限制；若需要更明确的动作描述，双方同时提供。只有短段可靠后，才优先处理生成历史分布和self-forcing。新正式训练仍需单独确定配方。

## 共同评判口径

- **画面与交互**：固定 train / heldout 各三窗的 pick-and-place 展示，短片看完整操作，长片看完整17块；复用 [统一可视化规范](../cosmos3_joint_video_hand_pose/visualization/README.md)。这六窗用于解释现象，不替代冻结 heldout8 / train16 的定量比较。
- **运动**：沿用 [V0.2 实验第15.2节](ar_v0.2/experiment.md) 的320×180整体光流口径，跨窗口/块先合并点积与平方范数再求余弦；幅值比为生成/GT，零范数记null。余弦接近0说明该指标下运动一致性低，不能单凭它证明运动随机或定位原因；相机、背景运动也会影响全图指标。
- **画质**：PSNR先合并MSE再换算；结合视觉检查，不能由PSNR推出方向正确或交互合理。幅值比接近1也不等于运动轨迹正确。
- **对照**：固定窗口、seed、采样步数、history模式与σ；注明checkpoint步数、训练集/heldout和原始时间轴。V0.2历史σ0与V0.3三档不可隐去。
- **结论**：保留负结果；像素差分“57%运动幅度”、由有限时移扫描推断“精确滞后4帧”、前缀“不可学习的噪声”、V0.3“持续越训越差”均不作为当前依据。MoBA或其他注意力结构改动暂不纳入本轮，也不把某个官方开关预设为质量修复。

后续每完成一项，只更新该项的证据、结论和状态；详细结果写入对应版本的 experiment.md，避免重复维护多份问题清单。
